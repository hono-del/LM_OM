## 3. モックの位置づけ（必ず最初に伝える）

```
モック = UX・画面フロー・文言の参照
本番   = API / CMS / IDP / サーバー永続化 / オフライン / プッシュ 等を新規実装
```

| モックの技術 | 本番でやるべきこと |
|-------------|-------------------|
| 静的 HTML + Vanilla JS | モバイルアプリ（RN 等）または本番 WebView |
| localStorage / sessionStorage | ユーザープロファイル API・端末キャッシュ |
| 固定 JSON（`demo-data.js` 等） | CMS / 通知 API / マニュアル配信基盤 |
| キーワードマッチの疑似 AI | AI エンジン + 出典付き回答 + オフライン FAQ |
| 独立 `onboarding.html` / `manual.html` | C-APP シェル内の画面統合 |

**開発チームへの一言:**  
モックの localStorage・固定データ・独立 HTML は**プロトタイプ限定**。Excel `C-APP_過剰独自実装_開発者共有要件.xlsx` の【本番】列を本番仕様として扱うこと。

1. **マニュアル完成（9月2週）→ デジタル配信（9月5週）→ 納車（9月末）の3段階連携**  
   → 各マイルストーンでアプリ側の受け入れテストをいつ実施するか（2週目・5週目・納車直前）。

2. **9月末納車に間に合わせるアプリ完成時期**  
   → 8月末 MVP 完了（要件ドキュメント記載）で十分か、9月前半の結合テスト期間を確保できるか。

3. **9月5週のデジタル配信と9月末納車の間（約1〜2週）**  
   → 予約購入者向けの先行アクセス（ベータ）を設けるか、納車当日まで待つか。

## 5. モックで「こう見せたい」UX（採用推奨）

開発チームに「この体験を本番でも再現してほしい」と伝える項目。

### 5.1 ナビ・画面構成（WBS 2.4 準拠）

- ボトムナビ: **Home / Chat / Manual / Notifications / Status**
- 警告灯はナビ外。ホーム 2×2 カード・通知・チャットから遷移

### 5.2 初回導線

```
ログイン → 車両選択（年式） → オンボーディング（スキップ可） → ホーム
```

- スキップと全完了を区別（全完了時のみ「ガイド完了」バッジ）
- 本番: ステップ数は **3〜5 に縮小** を検討（モックは7ステップで厚め）

### 5.3 チャット（部分実装済み → 本番拡張）

| トピック | モック | 出典 |
|---------|--------|------|
| 充電手順 | ステップ形式 + マニュアルリンク | 取説 3-(5) |
| 航続距離 | 仕様表 | [オートバックス公式](https://www.autobacs.com/product/micromobility/lean3/top.html) |
| アクティブリーン | 説明 + 最大リーン角28° | 同上（**Bluetooth は車両非搭載のため削除済み**） |
| 警告灯 | チャット内グリッド | マニュアル section5-2 等 |

- 各回答に 👍/👎、車両別履歴（本番はサーバー同期）

### 5.4 ホーム 2×2 お知らせカード（WBS 7.5）

- 4枚カード + タップでシナリオ起動（OTA / 日常Tips / 警告灯 等）
- モックの「カード既読履歴」→ 本番は **通知 API + ルールエンジン（7.7）**

### 5.5 Status タブ（WBS 9.1–9.6）

- 知識レベル・バッジ・機能カバレッジ・メンテナンス手入力
- 本番: サーバー永続化、テレマティクス連携前の暫定機能として有効

### 5.6 警告灯（WBS 6.1/6.2）

- 点灯2件強調 + 全9件グリッド + 検索
- ブレーキ警告の入庫先は **オートバックス**（モック反映済み）
- 予約・ロードアシスタンスの多段オーバーレイは **P1 以降** を推奨

## 8. マニュアル連携 — 9月2週目に向けた技術確認事項

モックの `manual.html` は **静的 JSON**（`data/manual-data.js`）。本番は **9月2週の XML/HTML** に置き換え。

開発チームに確認・合意してほしい項目:

1. **データ形式** — XML と HTML の役割分担、章 ID の命名規則（モックは `section3-5` 形式）
2. **配信方式** — アプリ同梱 / CDN / API 取得 / 初回ダウンロード + オフラインキャッシュ
3. **ディープリンク** — チャット出典・FAQ・通知から `?topic=` 相当で章ジャンプ（WBS 3.4）
4. **車両・年式切替** — 2.2 / 3.3 と連動してマニュアル差し替え
5. **画像・PDF** — パス規則、オフライン時の参照方法
6. **更新フロー** — マニュアル改訂時のアプリ更新要否（OTA vs 差分 DL）

## 9. 規模想定（1年目 3,000 ユーザー）で伝えること

| 観点 | 示唆 |
|------|------|
| 規模 | 3,000/年は小規模。過剰なマルチテナント設計は不要 |
| ピーク | 9月末納車開始後・10月にサポート・チャット・マニュアル参照が集中する想定 |
| 必須 | IDP、CMS、分析ログ（👍/👎、FAQ 利用）、エラー監視は初日から |
| オフライン | Lean3 は地方利用も想定。マニュアル・警告灯・FAQ のローカルキャッシュは MVP 要件 |
| コスト | AI 全問応答より、FAQ + 限定トピック出典付き回答の方が現実的（モックの方向性と一致） |
